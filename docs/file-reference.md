> **Plan Amendment 2 applied (2026-07-05):** 11 new per-payslip breakdown columns added to the `salary_history_pay_slips` manifest (all `real`, `nullable: false`, `default: 0`, `min: 0`): `shift_allowance`, `base_hourly`, `overtime_1_5x`, `overtime_2_0x`, `holiday_leave_loading`, `holiday_pay`, `public_holiday`, `payg_withholding`, `superannuation_guarantee` (9 monetary, $ per pay); `personal_leave_hours`, `holiday_leave_accrual_hours` (2 hours per pay). Total columns: 11 → 22. Closes the "lost on import" gap from Plan Amendment 1 for 7 of the 10 previously-lost xlsx columns (Tax → `payg_withholding`, Super → `superannuation_guarantee`, HLL → `holiday_leave_loading`, plus Shift Allowance / Base hourly / OT 1.5x / OT 2.0x). Adds 4 forward-tracking columns the xlsx doesn't currently track. See `docs/superpowers/plans/2026-07-04-phase4-shared-financial-data-salary-history.md` Plan Amendment 2 header for full rationale and design assumptions. 1 affected file description updated (`extensions/salary-history/package.json`); migration `004` grows from 11 to 22 columns.

> **Plan Amendment 3 applied (2026-07-05):** Calculation model inverts from CRUD-first to derivation-first — per-payslip inputs drop from 14 fields to 3 (`pay_date`, `gross`, `net`); all 9 monetary breakdowns derived from a new `salary_history_rate_history` table (13 columns, effective-dated temporal pattern) × optional hours fields. Six new hour-input columns added to `salary_history_pay_slips` (`regular_hours`, `shift_hours`, `overtime_1_5_hours`, `overtime_2_0_hours`, `holiday_hours`, `public_holiday_hours`); `finance_year` text column added. Total columns: 22 → 29. Migration count: 4 → 5 (new `005-salary-history-rate-history`). Four new decisions added (14 Calculation Model, 15 Reorderable Sections, 16 Rate History Table, 17 Two Commands/Two Views). PAYG validation via user's `CALCULATE_TAX_WITHHELD_26_27` wrapped as `payg-calc.ts`; triggered by user button (not auto). Settings: 4 new keys added (`paygToleranceDollars`, `paygTaxYear`, `financeYear`, `sectionOrder`). New second command `salary.show-pay-rate-history` reachable via Command Palette only. 6 new files added (3 services, 3 UI components) + 1 DAO wrapper + 4 new test files. Test counts: ~79 → ~119 new unit tests; project total ~144 → ~184. See Plan Amendment 3 header for full rationale.

> **Plan Amendment 4 applied (2026-07-05):** UI Design Finalization. 8 HTML/CSS mockups pre-approve the visual contract for all 6 Lit UI components at `docs/design/salary-history-mvp/` (per Decision 18). Implementation in Task 11 must match the mocks; visual parity check is Task 11.8. The mocks surfaced one structural correction: gross/net are user inputs in a dedicated **Totals** section between Period and Earnings (form now has 7 sections, not 6; `salary-history.sectionOrder` default updated to `["period","totals","earnings","deductions","super","leave","notes"]`). Other design decisions finalized: reconciliation warning as inline amber callout (with 4 action buttons), PAYG validation triggered by user button click, rate history with Current badge + green left border, rate row form pre-fills from current rate, reorder modal with up/down arrows + first/last row colored borders, accounts seed modal with Skip/Cancel/Create Account. See Plan Amendment 4 header in the plan + Decision 18 for full design rationale.

> **Plan Amendment 6 applied (2026-07-07):** Three small adjustments to the salary-history data model. (1) `salary_history_rate_history` gains `shift_allowance_hours_per_week` (real, default 38, min 0) — distinct from `standard_hours_per_week`, captures hours the shift allowance is paid on (eligibility varies by worker/shift pattern); 15 → 16 columns. (2) `salary_history_pay_slips` gains `personal_leave` (real, default 0, min 0, derived by `calculatePaySlipBreakdown` as `h.personal_leave_hours × rateRow.base_hourly_rate`); `personal_leave_hours` reclassified from persisted column to transient form input (still passed to calc, no longer stored). (3) `holiday_hours` reclassified the same way — transient form input feeding both `holiday_pay` / `holiday_leave_loading` derivations and `calculateHolidayLeaveAccrual`, no longer stored. `holiday_pay` and `holiday_leave_loading` derivations STAY (still derived from `h.holiday_hours × base_rate`). Total columns: 29 → 28. `calculatePaySlipBreakdown` defaults: `shift_hours` defaults from `rateRow.shift_allowance_hours_per_week` (per-payslip input still wins when supplied); new default `personal_leave_hours: 0`. New derived output `personal_leave`. `calculateHolidayLeaveAccrual` and the leave-balance tracking (Amendment 5) unchanged. Mocks updated: `docs/design/salary-history-mvp/rate-row-form.html` Rates section badge 9 fields → 10 fields; new `shift_allowance_hours_per_week` field adjacent to `shift_allowance_multiplier`. 1 affected file description updated (`docs/design/salary-history-mvp/rate-row-form.html`).
